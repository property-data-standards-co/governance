# Build rounds

Where argument cannot settle a question, it is built.

A build round is not a demonstration. It is a test with criteria agreed in
advance, run to find out whether something is true, and published whatever the
result. Charter §8 has the full description; this directory holds the record.

## The rule that makes them count

**Criteria are pre-registered by the working group, in the open, before any build
runs.** A round whose success criteria were set by the builder, or set after the
result was known, is discounted — openly and on the record — however good the
engineering. So is a round that could only ever have confirmed its builder's
position.

This is what allows participants with working implementations to contribute
evidence without that evidence being treated as advocacy. It cuts both ways, and
it is meant to.

## Participation

Open. A participant who cannot build contributes test cases, real-world data, or
acceptance criteria — and the step that most shapes the outcome is deciding what
the round has to demonstrate, which needs no engineers at all.

## Files

Each round gets `{PDR}-round-{n}.md`, created from `TEMPLATE.md` at
pre-registration, and updated once with results. The pre-registration commit is
the timestamp that matters; do not rewrite it.
